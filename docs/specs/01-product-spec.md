# 01 — 产品需求规范

**状态：Accepted**
**目标版本：MVP 0.1**

## 1. 产品定义

FoxSay Buddy 是一个“抬眼即可学习、拿起即可交互”的桌面学习伴侣。它不替代手机或完整学习平台，而是把低摩擦复习、进度提醒和情绪化反馈放在持续可见的小屏设备上。

核心价值按优先级排序：

1. 用极短交互完成一次学习动作；
2. 设备离线或网络波动时不丢学习记录；
3. 通过狐狸角色和姿态反馈形成陪伴感；
4. 与后端内容和学习记录保持可解释的一致性。

## 2. 目标用户与主要场景

首要用户是每天在固定书桌学习的中学生、大学生或自学者。MVP 聚焦三个场景：

- 用户抬眼看到时间、下一项学习倒计时和设备状态；
- 用户在 30–90 秒内浏览一组单词/公式，并标记公式难点；
- 内容和动作在网络恢复后同步，网页或后端可看到一致结果。

## 3. MVP 用户旅程

### J1 — 首次配对（P0）

1. 设备启动并进入配网页；
2. 用户通过手机为设备配置 2.4 GHz Wi-Fi；
3. 设备显示短配对码，用户在 Web/API 端绑定；
4. 后端下发设备证书/令牌与首批内容；
5. 设备进入主屏并显示同步完成。

验收：新设备在正常网络下 5 分钟内完成配对；失败有明确原因和可重试入口；日志不打印 Wi-Fi 密码或完整凭据。

### J2 — 待机与姿态休眠（P0）

- 主屏显示本地时间、同步状态、当前学习目标和狐狸待机动画；
- 设备稳定平放达到阈值后降低亮度并进入轻睡眠；
- 拿起或双击后恢复到之前页面；
- 网络断开不影响时钟与本地内容。

验收：误判率通过 30 次拿起/平放测试记录；唤醒后 UI 在 800 ms 内可见，目标值在 Phase 0 真机校准。

### J3 — 单词快速浏览（P0）

- 卡片显示单词、音标和简短释义；
- 单击任意非全局控制区域进入下一张；
- 到达末尾后显示本轮数量并回到主屏；
- 每次浏览动作写入本地 outbox，后台异步同步。

验收：连续快速点击 100 次不崩溃、不乱序；断网完成一轮后，恢复联网能完整上报且服务端不重复计数。

### J4 — 公式复习与难点（P0）

- 单击公式卡切换“公式/解释”两面；
- 上滑标记难点并进入下一张；
- 下滑跳过并进入下一张；
- UI 立即反馈，网络写入不得阻塞动画。

验收：每次动作在 100 ms 内出现视觉反馈；后端最终状态与最后一次动作一致。

### J5 — 内容同步（P0）

- 后端可向已配对设备发布一个内容包；
- 设备校验版本、大小和哈希后原子切换；
- 下载失败继续使用旧版本；
- 学习动作通过 MQTT 上报并获得业务确认。

验收：下载中断、校验失败、断电三种情况下均不破坏当前可用内容。

## 4. 范围

### P0（MVP）

- 设备启动、自检、配网、配对和凭据持久化；
- 时钟/待机、姿态休眠、音量/静音快捷面板；
- 单词卡、公式卡和难点标记；
- MQTT 在线状态、事件、命令、ack 与离线 outbox；
- 内容包下载、版本切换；
- 后端设备管理、内容包、学习事件和基本观测；
- OTA 基础链路与回滚验证；
- 一套最小本地开发环境。

### P1

- Wiki 新知左右划卡与层级导航；
- HTTPS 语音录制上传、翻译/情绪结果；
- Web 管理与学习记录界面；
- 健康提醒和 IMU 动作解锁；
- 更完整的动画和动态字体缓存。

### P2 / 非 MVP

- 实时全双工语音、UDP/WebRTC；
- 摄像头视觉理解；
- 像素小游戏；
- 社区推荐系统；
- 多用户共享同一设备；
- 完整离线 AI 推理。

## 5. 全局非功能需求

| ID | 指标 | P0 门槛 |
| --- | --- | --- |
| NFR-01 | 可用性 | 无网络时主屏和已缓存卡片仍可用 |
| NFR-02 | 数据可靠性 | 已接受的本地学习动作在断网恢复后最终送达，不重复计数 |
| NFR-03 | UI 响应 | 触摸反馈 p95 < 100 ms；常规动画目标 ≥ 25 FPS |
| NFR-04 | 稳定性 | 8 小时 soak test 无崩溃、无持续内存下降 |
| NFR-05 | 启动 | 冷启动到可用主屏目标 < 5 s（真机校准） |
| NFR-06 | 安全 | 每设备独立凭据、TLS、配对码短时有效、秘密不可进入日志 |
| NFR-07 | 可升级 | OTA 失败自动回滚到上一个可启动版本 |
| NFR-08 | 可观测 | 后端能按 device/message/request 关联问题，设备保留有界诊断日志 |

## 6. 成功指标

MVP 内测至少记录：配对成功率、日活设备数、每轮卡片完成率、动作同步延迟、断线次数、崩溃/重启原因和 OTA 成功率。首轮目标不预设商业 KPI；在 10 台、7 天 dogfood 后用真实基线设目标。
